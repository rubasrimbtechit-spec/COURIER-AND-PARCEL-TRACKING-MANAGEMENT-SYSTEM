# Run and deploy the Courier Parcel Tracking System

## 1. Extract and open
Extract `Courier_Parcel_Tracking_System_Deployment_Ready.zip`. In VS Code choose **File → Open Folder** and select the extracted `Courier_Parcel_Tracking_System` directory (the directory containing `Backend`, `Database`, and `README.md`). Install the Extension Pack for Java if desired.

## 2. Requirements
- JDK 17 (or newer compatible JDK; project targets Java 17)
- Maven 3.8+
- MySQL 8.0+ (or compatible hosted MySQL)
- Docker Desktop for the one-command container option

## 3. Local MySQL
Create a database and user, then execute `Database/schema.sql` followed by `Database/sample_data.sql` in MySQL Workbench or the MySQL CLI. Schema creation is non-destructive and uses `IF NOT EXISTS`; sample rows use fixed academic demo IDs and should be loaded into a fresh database to avoid conflicting IDs.

Example user setup (run as a MySQL administrator; choose your own password):
```sql
CREATE USER 'courier_app'@'localhost' IDENTIFIED BY 'your_local_password';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE VIEW ON courier_tracking.* TO 'courier_app'@'localhost';
FLUSH PRIVILEGES;
```
If schema is run by the app user, it needs database creation privileges. Safer: run schema as administrator first, then grant only data privileges:
```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON courier_tracking.* TO 'courier_app'@'localhost';
```

## 4. Run the Spring Boot website
In a terminal:
```bash
cd Backend
```
Set environment variables with your actual local MySQL credentials.

PowerShell:
```powershell
$env:DB_URL='jdbc:mysql://localhost:3306/courier_tracking?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
$env:DB_USER='courier_app'
$env:DB_PASSWORD='your_local_password'
mvn spring-boot:run
```
macOS/Linux:
```bash
export DB_URL='jdbc:mysql://localhost:3306/courier_tracking?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
export DB_USER='courier_app'
export DB_PASSWORD='your_local_password'
mvn spring-boot:run
```
Open `http://localhost:8080`. API reference: `Backend/API.md`.

## 5. Docker local deployment
From the `Deployment` directory, copy `.env.example` to `.env`, set strong values for `DB_PASSWORD` and `MYSQL_ROOT_PASSWORD`, then run:
```bash
docker compose up --build
```
Open `http://localhost:8080`. Stop with `docker compose down`; persistent MySQL data remains in the named volume. `docker compose down -v` also deletes that volume and its data.

## 6. Public deployment (Railway or Render)
The ZIP includes `Backend/Dockerfile`, `Deployment/railway.toml`, and `Deployment/render.yaml`. Commit and push the extracted project to GitHub. Create a managed MySQL 8 database with network access from the application host. A separate database service may incur charges; verify current pricing, storage, backups, outbound networking and sleep/usage policies with the provider before provisioning. Do not assume a free database or always-on web service is available.

Configure the web service to build using `Backend/Dockerfile` (Railway config is supplied; for Render use the included blueprint). Add these environment variables in the host dashboard:
- `SPRING_PROFILES_ACTIVE=prod`
- `DB_URL`: full JDBC URL, e.g. `jdbc:mysql://HOST:3306/DBNAME?sslMode=REQUIRED&serverTimezone=UTC` (use exact host, port, database and TLS parameters supplied by the database vendor)
- `DB_USER`: hosted database username
- `DB_PASSWORD`: hosted database password
- `PORT`: assigned automatically by most platforms

Allow the web host's outbound network/IP in the database firewall if required. Keep credentials in host secret settings, never in Git. Apply `Database/schema.sql` and optionally `Database/sample_data.sql` to the hosted database using a secure SQL client/provider console before first use. Confirm network access and successful Spring Boot startup in logs.

After deployment, open the web service dashboard and copy its generated public domain. That is the public URL. No public URL is generated by this project and no deployment is performed by packaging this ZIP.

## 7. GitHub
From the extracted project root:
```bash
git init
git add .
git commit -m "Deploy courier parcel tracking web application"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/Courier_Parcel_Tracking_System.git
git push -u origin main
```
Replace the remote with your own repository URL. `.env`, credentials, Maven targets and IDE files are ignored.

## 8. Security and operational notes
This is an academic operations portal, not a production-hardened multi-tenant service. It does not currently implement login/role-based access control, CSRF protection for authenticated sessions, rate limiting, audit-user identity, or privacy/retention workflows. Before exposing it to the public internet with real customer data, put it behind authentication (for example, an identity-aware proxy or a properly configured Spring Security layer), restrict database network access, enable TLS, use backups, and review applicable privacy requirements. Do not expose an unauthenticated admin interface containing personal data.
